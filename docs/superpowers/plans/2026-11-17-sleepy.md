# Sleepy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An offline-capable PWA that plays the owner's encrypted sleep sessions on iOS and Android, hosted free on GitHub Pages.

**Architecture:** Static site, plain ES modules, no build step. Pure logic (crypto format, catalog, prefs, sync planning) lives in small modules tested with `node --test`; browser-only glue (IndexedDB, audio, DOM) is thin and verified manually. Owner tools are Node scripts that encrypt audio and maintain `catalog.json`.

**Tech Stack:** HTML/CSS/JS (ES2022 modules), Web Crypto (AES-256-GCM, PBKDF2-SHA256), IndexedDB, Service Worker, Media Session API, Node 24 (`node:test`, no npm dependencies), macOS `sips` and `afinfo`.

**Spec:** `docs/superpowers/specs/2026-11-17-sleepy-design.md`

## Global Constraints

- No npm dependencies, no framework, no build step. `package.json` only for `"type": "module"` and `"test": "node --test"`.
- PBKDF2-SHA256, **600 000** iterations, 16-byte random salt; AES-256-GCM, 12-byte random IV.
- File magic: ASCII `SLPY1`. Audio file = `SLPY1 · iv(12) · ciphertext+tag`. `key.enc` = `SLPY1 · salt(16) · iv(12) · ciphertext+tag` (plaintext = 32-byte content key).
- Unencrypted audio and the password never enter the repo (`.gitignore`: `.superpowers/`, `tmp/`, `*.m4a`, `*.mp4`).
- Every file served by Pages ≤ 100 MB; total site ≤ 1 GB.
- Always dark. No white screens, no popups, no in-app instructions.
- Colours from the approved "Dusk" mockup: background gradient `#2a1d45 → #1a1530 → #120f22`, sheet `#2b2050 → #1a1532`, secondary text `#b8a9d6` / `#c3b5e0`, primary buttons white with text `#2a1d45`.
- App name "Sleepy". Groups: "Falling asleep", "Back to sleep". Hero label: "Last played".
- Remembered on device: last played session + sound, last sound per session. Nothing else (no positions).

## Review Focus

1. **First download interrupted** (app closed, network drops mid-unlock) → finished tracks are kept, no half-written track is stored, next launch resumes. *Test in Task 4:* `sync keeps completed tracks and stores nothing for a failed one`.
2. **Password typed on a phone** (auto-capitalised first letter, trailing space from autocomplete) → field has `autocapitalize="off" autocorrect="off" spellcheck="false"`, and the value is trimmed. *Test in Task 1:* `normalizePassword trims surrounding whitespace`.
3. **Catalog changed since last play** (session or sound removed/renamed) → hero card hidden, no crash; stale last-sound falls back to first sound. *Test in Task 2:* `resolveLastPlayed returns null for unknown session or sound`, `preferredSound falls back to first sound`.
4. **Tracks missing on device while the key exists** (iOS cleared part of storage, or new tracks published) → those tiles show "Preparing…" and are downloaded in the background. *Test in Task 2:* `planSync downloads files missing from store and removes files not in catalog`.
5. **Track ends while the phone is locked** → playback stops, nothing else starts, play button restarts from 0:00. *Checked in Task 6 manual steps and the Task 8 device checklist.*

### Catalog schema (used by Tasks 2–7)

```json
{
  "groups": [ { "id": "falling-asleep", "title": "Falling asleep" },
              { "id": "back-to-sleep",  "title": "Back to sleep" } ],
  "sessions": [ {
    "id": "unwind", "title": "Unwind the Day", "group": "falling-asleep", "cover": "unwind",
    "sounds": [ { "id": "music", "label": "Music", "file": "audio/unwind-music.3fa9c210.enc", "duration": 1769.0, "bytes": 42412345 },
                { "id": "rain",  "label": "Rain",  "file": "audio/unwind-rain.91bd02aa.enc",  "duration": 1771.0, "bytes": 42460000 } ]
  } ]
}
```
Single-sound sessions have one sound; its `label` may be `null`. `cover` is the basename for `covers/<cover>-600.jpg` / `-1200.jpg`. A file name changes whenever its content changes (hash suffix), which is how phones detect replaced tracks.

- Produces (`js/crypto.js`, works with `globalThis.crypto` in browser and Node):

  - `wrapContentKey(rawKey: Uint8Array, password: string): Promise<Uint8Array>`
  - `unwrapRawKey(keyFile: Uint8Array, password: string): Promise<Uint8Array>` – same errors as above
  - `encryptAudio(plain: Uint8Array, rawKey: Uint8Array): Promise<Uint8Array>`
